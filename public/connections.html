← DevelopersConnection & Adaptation Layer

Connect external systems without surrendering source-of-record boundaries.

A connector establishes access. An adapter translates provider-native resources and actions into the OMOS common contract. OMOS then applies policy, provenance, Human Gate requirements and audit rules before a capability is used.

EXTERNAL PLATFORM → ADAPTER → OMOS CONNECTION GATEWAY → OMOS RUNTIME → ALGORITHM → DECISION / ACTION → ADAPTER → EXTERNAL PLATFORM

Model Connections

OpenAI, Anthropic, Gemini, xAI and future OLLM providers.

Data Connections

GitHub, Google Drive, databases, WordPress, Notion and other approved source systems.

Action Connections

GitHub, WordPress, Stripe, email, calendar and deployment actions, with explicit write authorization.

Environment Connections

Blender, Unreal, local runtimes, robotics, IoT and XR environments where separately approved.

Normalized interface

connect() · authenticate() · capabilities() · health() · read() · search() · invoke() · write() · subscribe() · cancel() · disconnect()

Configured capability is not authorization. Write access and consequential execution remain least-privilege and Human-Gate controlled.
