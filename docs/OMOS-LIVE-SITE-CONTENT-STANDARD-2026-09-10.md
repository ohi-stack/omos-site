## Seven-stage customer runtime

Ask OMOS → Layer 1 / Distill → Alignment → Council Review → Governed Synthesis → Decision Record → Dashboard History.

The OneGodian Algorithm retains its canonical operating cycle:

Observe → Distill → Align → Select → Execute → Verify.

## Primary live-site experiences

### Ask OMOS
Customer entry point for questions, decisions, document analysis, option comparison, and Council-eligible runs.

### OMOS Distill
Consumer-facing name for Layer 1. It should identify objective, facts, claims, requirements, constraints, contradictions, missing information, risks, quarantined instructions, and a clean working prompt without material distortion.

### Alignment Engine
Expose dimension-level analysis and hard gates. Do not market a single opaque score as mathematical truth.

### Compare AI Perspectives / Council
Consumer-facing Council experience. Show agreements, contradictions, omissions, missing evidence, novel insights, supported dissent, provider provenance, and degraded-provider status.

Rule: model agreement is not factual verification.

### Governed Synthesis
Return conclusions, evidence status, uncertainty, dissent, alternatives, recommendation, and human-review requirements.

### Decision Record
Persist input, versions, timestamps, hashes, Layer 1 state, alignment, Council provenance, synthesis, human disposition, verification state, and revision lineage where production persistence is enabled.

### Dashboard History
Allow authorized users to search, reopen, inspect, compare, replay where supported, and export their prior governed runs.

## Flagship product

OMOS Decision is the primary consumer experience. A decision result should contain:

1. Decision Summary
2. What is known
3. What is not known
4. Assumptions
5. Options
6. Risks
7. AI agreement/disagreement where Council is used
8. Recommended path
9. Conditions that would change the recommendation
10. Confidence/evidence state
11. Human-review requirement
12. Decision Record where persistence is available

## Customer funnel

Try a real question free → Distill → structured OMOS analysis → Decision Record → usage/feature boundary → upgrade → Council/history/projects/exports → Team/Business.

## Public maturity language

Use the component maturity model:

Conceptual → Prototype → Functional → Verified → Production.

Never imply blanket Production status. Functional means available for controlled validation with known limitations. Provider configuration is not the same as a successful live connection test. Simulation, Hybrid, Live, and Degraded modes must be explicit.

## Verification and safety boundary

- Council convergence is comparative evidence, not factual verification.
- Deterministic processing does not guarantee truth.
- Consequential decisions remain human-authorized.
- Evidence support, uncertainty, and verification state remain separate fields.
- External execution involving money, legal records, credentials, registries, or infrastructure requires separately authorized execution controls.
- OMOS does not replace qualified legal, financial, medical, tax, or other professional advice.
