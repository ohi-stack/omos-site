# OMOS Live Capability Standard

## Current Classification

**System:** OMOS — OneGodian Metaphysical Operating System  
**Platform:** OMOS.OneGodian.com  
**Current status:** Functional  
**Definition:** Available for controlled validation with known limitations.  
**Human oversight:** Required  
**Consequential execution:** Restricted  

OMOS must be classified module-by-module. A public route may be live while a deeper runtime feature remains Prototype, Specification-Ready, or Planned.

## Live Role

OMOS.OneGodian.com is the central runtime and operating environment for:

- The OneGodian Algorithm™
- OHI™ synthesis
- The OneGodian Protocol™
- model and agent orchestration
- high-entropy prompt processing
- identity-aware interaction
- structured decision support
- developer documentation
- plugin bridge coordination
- auditable decision records

### Required Safety Label

The UI must show whether a run is:

- Simulation Mode
- Live Model Mode
- Human-Reviewed
- Execution-Approved
- Verification-Partial
- Verification-Failed

No screen should imply external AI APIs were called unless the runtime actually called configured server-side provider adapters.

## WordPress Plugin Bridge Standard

The plugin installed on OneGodian.org, OneGodian.com, and QuantumOHI.com should operate as a distributed OMOS client, not as three disconnected OMOS systems.

Minimum bridge capabilities:

- runtime status check
- manifest sync
- tool registry sync
- embedded OMOS shortcodes or blocks
- Ask OMOS launcher
- Council Review launcher
- site context identification
- authentication handoff target
- run status display
- artifact return pathway
