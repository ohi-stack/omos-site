OneGodian LLM

OLLM is the OneGodian intelligence/model layer designed to participate inside OMOS through the same governed provider contract as other models. It is not a replacement for OMOS, O-H-I, or the Council.

Role

Provide OneGodian-aware model output, source-aware context, evaluations, streaming, health, and provenance through a native OMOS connector.

Boundary

OMOS remains the runtime and orchestration layer. O-H-I remains the comparison, critique, synthesis, and human-reviewed intelligence process.

Current maturity

Architecture defined. Native runtime participation is not yet production-proven and must not be represented as live until connector, health, inference, evaluation, and provenance tests pass.

Native provider requirements

OLLM must expose model/version identity, capabilities, availability, health, invoke, stream, review, retry, cancel, latency, usage, estimated cost where applicable, request identifiers, errors, and provenance. The same degraded-state rules used by the Council should apply.

Authoritative context

The OLLM context hierarchy should prioritize versioned OneGodian source material—Protocol, Algorithm, OMOS architecture, O-H-I, OTS-V5, institutional classification, approved policies, schemas, chronology, and operating documents—while keeping source status and version visible.
