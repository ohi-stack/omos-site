OMOS-REF-0001 is the reference-run standard for proving that OMOS is not merely implemented in source code, but operating correctly on the canonical production runtime. This page does not self-certify production status. A PASS requires verifiable evidence for all nine gates below.

05

06

The complete record is saved with provenance, timestamps, version state, and hashes.

07

Restart Test

The production runtime is restarted or redeployed after the record is created.

08

Persistence Proof

The exact Decision ID and human disposition survive the restart.

09

Dashboard Reopen

Dashboard History finds and reopens the exact same Decision Record with lineage intact.

Certification rule

PASS only when all nine gates have production evidence. A successful-looking run that disappears after restart is an automatic FAIL. A merged commit is not proof of deployment, and a deployment is not proof that the required production behavior works.

Status vocabulary
Functional means implemented enough for controlled validation. Verified means the relevant behavior has passed defined tests. Production applies only to the specific component/revision demonstrated to be running and working in the intended environment. Use MERGED_NOT_DEPLOYED and DEPLOYMENT_READY when those are the accurate states.
