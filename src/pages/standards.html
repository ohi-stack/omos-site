The specifications behind OMOS behavior.

OMOS separates operating code from standards that define expected behavior. Each standard must display its own version and maturity; a draft specification is not the same thing as a production-certified implementation.

Core standards

  • OneGodian Protocol — identity, semantic, alignment, agent-interaction, governance, verification, and interoperability guidance. Current protocol material includes working-draft specifications.
  • OneGodian Algorithm — Observe → Distill → Align → Select → Execute → Verify.
  • OMOS Runtime Specification — runtime stages, Human Gate, Decision Record, persistence, provider and verification boundaries.
  • OMOS Compliance Test Suite (OMOS-CTS) — conformance framework for schema validation, sequencing, alignment logic, response modes, dignity/truth constraints, prompt enforcement, API behavior, error handling, verification integrity, and robotics safety where applicable.
  • Connection & Adaptation Layer — provider-neutral integration contract.
  • Council Provenance Standard — attribution, hashes, execution provenance, dissent preservation, and correction discipline.
  • OneGodian MCP Standard — controlled interoperability for eligible resources, tools, and workflows.
  • OTS-V5 — current OneGodian Timekeeping System standard; formal civil/legal system records retain the applicable civil timestamp authority.

Conformance principle

An implementation should not claim compatibility simply because a document exists. Conformance requires applicable tests, expected schemas and state transitions, and evidence from the implementation being certified.

Claims discipline

Some standards remain drafts or implementation tracks. Their presence in the library documents direction and requirements; it does not automatically elevate the corresponding runtime capability to Production.
