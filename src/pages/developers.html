Canonical Engineering Council

GitHub Issue → Task Classification → Agent Assignment → Agent Work → Pull Request → Cross-Agent Review → Tests / CI → OMOS Review → Human Approval → Merge → Deployment Proof → Engineering Record.

No implementation agent is the final reviewer of its own work. Green CI is necessary but not sufficient. Consequential changes do not auto-merge. A merge is not completion; production proof must identify the exact deployed SHA and show the required behavior.

Engineering task states

INTAKE → CLASSIFIED → ASSIGNED → WORKING → PR_OPEN → CROSS_REVIEW → CI → OMOS_REVIEW → HUMAN_APPROVAL → MERGED → DEPLOYING → PROOF → COMPLETE. Hold/failure states: BLOCKED, NEEDS_REVISION, REJECTED, ROLLED_BACK.

Risk classes

R0 documentation/non-executable · R1 low-risk UI/content · R2 application logic/API/schema · R3 authentication/payments/data/migrations/infrastructure · R4 production/security/destructive/high-impact. R3 and R4 require stricter independent review, human approval, and deployment proof.

Agent roles

GitHub/Copilot coding agent may handle issue-native implementation and PR maintenance; Codex may handle deeper implementation, refactors, APIs, tests, and debugging; Antigravity may perform browser/application validation and independent implementation testing; GitHub Actions supplies deterministic CI; OMOS supplies governed review and provenance; the designated human authority remains the final merge/deployment approval boundary.
