MCP • Interoperability • Governed Tool Access

MCP is an interoperability layer inside the OneGodian operating architecture.

OMOS should not be reduced to an MCP server. MCP provides a standardized way for compatible clients to discover and use resources, tools, and workflows. OMOS remains the governed operating/runtime layer; ACC supervises operational execution; domain systems retain their own sources of record.

Logical hierarchy

OMOS → OHI / verification architecture → ACC → policy and execution controls → OneGodian MCP layer → domain systems and external tools.

What MCP should expose

Only systems that have useful resources, authoritative data, tools, workflows, or authorized actions should receive MCP support. MCP itself should not become the authoritative registry, ledger, identity database, financial system, or Decision Record store.

Authorization

Tool discovery is not permission to execute. Read/write scopes, identity, policy, Human Gate requirements, audit logging, provenance, rate limits, and verification policies remain part of the surrounding OneGodian connection and execution architecture.

Current maturity

The OneGodian MCP architecture is a technical standard and implementation track. Individual MCP servers, gateways, clients, and conformance claims must be labeled according to their actual deployed and tested state.
